# 估算政策

## 三档含义

- 低值：只计入已确认交付物和最低合理人工替代时间。
- 中值：加入多源读取、整理、调试和复核的常见工作量。
- 高值：只作为敏感性分析，不能作为日常汇报主结论。

## 估算原则

1. 人工反事实是“用户独立完成同等结果可能耗时”，不是代码行数乘系数。
2. 用户主动参与只计提问、澄清、选择、检查和要求返工的时间，不计 Agent 后台运行时间。
3. 复杂文档、资料研究、数据管线、自动化、代码排障和发布可以使用较高人工区间；简单问答和一条命令只给很小节省或不入账。
4. 多轮迭代只有在交付物边界明显不同、且没有被上一条涵盖时才拆成多条。
5. 代码量、文件量、记录量和运行时长属于复杂度证据，不直接等于价值。
6. 价值估算必须写明假设、未验证范围和是否分摊 Agent 成本。

## 质量门槛

- `high`：有明确交付物、可回读/测试/发布验证，任务类型和边界清楚。
- `medium`：交付物清楚，但人工反事实或验收范围存在不确定性。
- `low`：来源或完成态较弱，只能作为待审阅候选，不应进入主结论。

## 典型反作弊检查

- 不把“写了很多代码”直接换算成几百小时。
- 不把 Agent 运行时长当作用户节省时间。
- 不把可能产生的未来复用收益提前计入当前任务。
- 不把现金收入、利润、薪资或客户收益写成已经实现的金额。
- 不为弥补扫描遗漏而重复计入已存在的任务。
