# 脱敏与证据边界

## 保留

- 任务短标题、工作日期、任务类别和一句话摘要。
- 可公开的交付物类型，例如“测试报告”“本地脚本”“Excel 模板”。
- 稳定但不可逆推个人身份的来源 ID；公开发布前可进一步替换为 `source-001`。
- 验证结果的短结论，例如“公式扫描通过”“重复运行新增 0 条”。

## 删除或替换

- 姓名、邮箱、手机号、账号、令牌、Cookie、API Key 和完整 URL 中的私有 token。
- 公司客户名、内部域名、私有仓库地址、飞书文档链接和本机用户名路径。
- 完整聊天、完整文档、原始 JD、私密财务数字和任何凭证。
- 能够还原真实项目或个人身份的文件名、截图和日志片段。

## 发布前检查

1. 对文本和二进制文件做敏感词与密钥模式扫描。
2. 确认工作簿只包含虚构示例，没有真实历史记录。
3. 打开工作簿，验证关键公式无 `#REF!`、`#VALUE!`、`#DIV/0!`、`#NAME?` 或 `#N/A`。
4. 运行 Skill 结构校验并检查 `agents/openai.yaml` 与 `SKILL.md` 的名称、描述一致。
5. 逐项确认仓库中没有个人路径、租户信息和外部系统专属流程。
